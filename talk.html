1. The problem Velocity solves

Say Deploying Node usually means two bad options. A raw VPS: you install Node, wire Nginx, run PM2, and own SSL. Or serverless: cold starts and a bill that moves with traffic.

Say Velocity is the third option. Connect a GitHub repo. The platform builds, runs, and deploys on every push. Persistent server, flat price, no SSH to ship.

Click Cloudways console open on the Velocity app. GitHub tab ready on ankitha-p/velocity-art-show. Live site in a third tab.

3. Git in, app out

Say I created a Velocity application, connected GitHub, picked this repo and main. Velocity read package.json, saw Next.js, and set npm build and start. I did not write an Nginx file. I did not install PM2.

12:00–16:00 · env vars

5. Change the event live, no commit

Say Date and venue should not live in Git. They are environment variables on the application, not on a single deploy.

Click Leave the home page visible (When / Where cards). Environment Variables: EVENT_DATE = 8 December 2026, EVENT_VENUE = Jawahar Kala Kendra, Jaipur. Optional: tweak EVENT_NAME. Save and redeploy. Wait. Hard-refresh.

Say Same code. New When and Where. Footer updated. Env vars need a redeploy so the Node process restarts. They do not need a git push. Rollback of code will not undo these values.

16:00–18:00 · rollback

6. Go back

Click Deployment Management. Roll back to the v1 deploy. Refresh the live site.

Say Version and theme go back because they live in code. Date and venue stay Jaipur because env vars belong to the app. That difference matters in production.

18:00–20:00 · sidebar, then close

7. What else is on the plan (do not demo all of it)

  • Security: SSL on the default URL. HTTPS redirect so http becomes https. Optional password gate for staging, not for this public hanging. IP allow/block for SSH or site traffic. WAF, malware, and DDoS are on the Velocity plan (Cloudflare at the edge).
  • Domain / Cloudflare: map a real hostname later. CDN and DDoS sit in front of Nginx.
  • Web Rules: redirects and headers in the UI. No server file.
  • Backup: restore files and data. Different from deploy rollback (code only).
  • Staging / Cron / Access: clone to test, schedule jobs on a persistent process, SSH if you must. Git is still how we ship.

Say Close: I shipped a real Next.js app from GitHub, updated it with a push, changed production config without a commit, and rolled back. I did not hire a sysadmin for Nginx, PM2, or SSL. That is Cloudways Velocity.
